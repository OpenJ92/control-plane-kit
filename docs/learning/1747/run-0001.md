## #1764 chosen shape and review learning

The law-context preceded source dry run and tests. Inline preparation's existing
session -> desired publication -> plan -> approval-request composition cannot
consume a saved graph unchanged: it would copy/re-publish identity and increment
generation. Starting the session first would also record evidence before saved
admission. A bounded saved-admission service therefore validates exact selection
and full lineage fences before the existing session/start action commit. The
session writer is extracted into a transaction-taking operation; it retains the
same owner, fingerprint/action semantics and never commits its caller's UoW.
The existing DeploymentProgram then uses unchanged planning/approval services.
No generic workflow hook, new planner or all-stage transaction was added.

Lock order is session idempotency key -> workspace -> draft before a new session
exists. Later stages retain their own session/workspace locks and commit
boundaries. Admission is not a reservation: later selection drift blocks first
planning, leaving truthful partial session evidence. Completed replay resolves
historical coordinates before mutable admission. Exact inline v1 digests, child
keys and restart behavior remain governing tests.

Meridian initially held the test packet because metadata/digest closure was only
partly executable. The corrected packet fixes all nine string fields, an exact
saved marker and seven reserved keys; independently computes canonical intent;
tests every orphan/missing key and each lineage/generation corruption; and
requires the admission owner to compute the digest. Overview uses only its
already-selected plan/session, validates the committed mapping, and returns a
bounded prepared coordinate. Complete erasure of saved metadata cannot be
distinguished from legacy and is documented rather than inferred.
