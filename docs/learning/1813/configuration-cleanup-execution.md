## Objects, transformations, and authority

The existing approved cleanup proposal selects K exact allocations, U complete
original invocations, and D protecting claims. A fresh start revalidates those
objects under the existing lifecycle/request/run locks and returns a private
preparation tied to the exact object, transaction, stores, connection, accounting
ledger, and thread/task. A copy or expired preparation grants no write authority.

Start writes the normal event, immutable intent and attempt together with the
reservation, complete members, invocation closures, claim closures, and paired
claim/ref dispositions. Only successful transaction completion returns
`NewlyStarted`. Protective columns are generated by the schema from the three
cleanup locators; the writer updates locators and verifies acknowledgments,
rather than assigning generated columns.

Before dispatch, the coordinator reads complete retained cleanup proof and checks
the originally pinned registration against the authority selected in its earlier
context. Registration equality includes workspace, reference, kind and identity.
The read transaction ends before any adapter call. A mismatch does not retarget
authority: it becomes canonical UNKNOWN/NOT_ATTEMPTED through normal fold.
Unavailable or over-budget proof preserves committed STARTED and refuses dispatch.

Fold writes the normal outcome/event/CAS and complete per-member outcomes in one
transaction. It validates pending rows and exact relational correspondence before
members are complete, then proves the complete terminal aggregate. Dispatched
results and historical replay use original authority identity, not a new
requirement that its registration still be active. Generic observations retain
the reservation but cannot create per-member retirement evidence.

## Evidence accounting and failure semantics

One command ledger spans coordinator prelude, fresh checks, captures, start,
dispatch correspondence, fold, and continuation. Preflight adds only remaining
work to the actual prefix; it neither erases used charges nor raises limits.
Reservations use fixed owner projections and captured column maxima/counts.
Failed SQL retains its pre-execution reservation. The initial command receipt
INSERT and terminal run CAS are charged at their existing execution-store owners.
An oversized matched CAS row refuses with rollback instead of looking like a miss.

Invalid adapter results, exceptions, wrong effect IDs, and nonconserved results
produce total UNKNOWN/PROVIDER_UNCERTAIN for the original candidates, without raw
provider messages. Known refusal before a call produces NOT_ATTEMPTED. Valid
mixed known/unknown outcomes survive unchanged. An incomplete command retry may
report uncertainty without dispatch or automatic observation; explicit
reconciliation remains a separate existing action.

## Law provenance and test honesty

The #1939/#1941 historical refusal checks were temporary activation guards.
Their source-read, accounting, identity/lifetime, and transport laws remain.
#1936 supersedes only blanket "cleanup unsupported" assertions with actual
approved public execution and scope/runtime-binding denial tests. Historical
learning documents retain their stage-specific truth.

Actual-public targets compose ordinary admitted D1, departure/acceptance, cleanup
publication/destructive approval, admission, lifecycle, start, coordinator and
fold. Their adapters simulate Operations evidence; they prove no provider deletion.
Negative transport/corruption fixtures are explicit and always roll back, including
when an expected assertion fails. No current schema validation is weakened.

Current membership needed for ordinary reuse conflicts with fresh cleanup's
absence-of-current-use condition. Do not manufacture a same-allocation race by
bypassing either owner. Recorded-history defensive exclusion remains distinct
from actual cleanup-vs-acceptance and competing-cleanup execution targets.

## Security, data, and remaining validation

No schema, credential, provider, deployment, network exposure, or replacement
policy is introduced. All runtime mutations require the exact approved proposal,
authority scopes, original runtime binding, claim fence and live lease. No database
transaction spans the external adapter. Lost commit acknowledgment is distinct
from confirmed rollback; original replay allocates no new permission or IDs.
