## #1796: separate runtime connection context from process permissions

The fixture audit found that remote observation tests used process TLS delivery
to admit the credentials needed by CPK's own Docker connection. Those are
independent powers. Adding process permissions to every remote fixture would
preserve that coupling and conceal missing recipient checks.

This prerequisite adds `RemoteDockerTlsConnectionAdmission` and two pure
functions in Core's existing `runtime_authority` owner. The value has an exact
authority reference and three typed, repr-private secret references. Fixed slots
derive only the existing CA certificate, client certificate, and client key
intents. A reference reused in different roles is valid; duplicate exact
reference/intent grants are invalid. The public descriptor redacts all credential
references and is intentionally not a storage codec.

```python
connection = RemoteDockerTlsConnectionAdmission(
    authority_ref=RuntimeAuthorityReference("remote-docker"),
    ca_certificate=SecretReference("secret://example/docker/ca"),
    client_certificate=SecretReference("secret://example/docker/certificate"),
    client_key=SecretReference("secret://example/docker/key"),
)
uses = runtime_connection_secret_uses(
    connection, authority_ref=RuntimeAuthorityReference("remote-docker")
)
```

`validate_runtime_connection_grants` checks every supplied connection grant for
exact use, uniqueness, and workspace/effect/run/activity correlation. Empty or
partial grant tuples are structurally valid; the interpreter must require all
three before resolving credentials or connecting. Absent connection admission
admits no connection grants. Operations remains responsible for selecting the
active authority in the correct workspace and authorizing secret use.
