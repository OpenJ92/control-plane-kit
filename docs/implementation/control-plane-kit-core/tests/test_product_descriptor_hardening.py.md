Three tests add concrete rejection, nonmutation and source-boundary evidence around product documents. The fixture first round-trips a pure container-server product through the codec, then builds a document mapping. The HTTP provider and registry coordinates are fixture data; nothing is pulled, launched or contacted.

The five-case matrix modifies a deep copy of that mapping with embedded registry credentials, a configuration artifact targeting the Docker socket, an unknown telnet protocol, shell-shaped description text or an extra allowed_registry policy claim. Each must raise ProductDescriptorError whose displayed message omits one canary. Only the registry-credential input actually carries that canary. These assertions do not check message length, cause/context, logs or all sensitive values, and are weaker than the selected mapping-admission checks in [test_product_descriptor.py](test_product_descriptor.py.md).

Selected [product codec paths](../../../../control-plane-kit-core/src/control_plane_kit_core/products.py) delegate registry syntax to the OCI value, protocol interpretation to [Protocol.from_descriptor](../../../../control-plane-kit-core/src/control_plane_kit_core/types.py), and artifact decoding to [ConfigurationArtifact](../../../../control-plane-kit-core/src/control_plane_kit_core/configuration.py). Product text uses a finite forbidden-fragment check; unknown product fields fail the closed descriptor boundary. Nested codec errors may retain chained causes. Rejecting an allowed_registry field prevents that field from becoming product language; it does not establish an operator's actual registry policy.

The path-abuse fixture also has a mismatched artifact content digest. Current artifact construction checks the reserved path before digest equality, but the test asserts only outer ProductDescriptorError. It would still reject if a different invalid part caused the failure; it is not an isolated regression test for that path rule. Likewise, rejection of shell-shaped prose is not proof of a general shell-safety property, and no command is executed by this test.

The catalogue test adds one document, attempts a different image digest and description under the same identity, then checks that products and lookup still return the first document after ProductCatalogConflict. It proves preservation for this particular rejected add, not rollback of external state, concurrent catalogue mutation or every merge failure. The actual catalogue uses new values for successful additions; its broader examples are described in [test_product_catalog.py](test_product_catalog.py.md).

The final AST test inspects products.py for nine forbidden import roots and direct calls named __import__, eval, exec or open. It does not resolve aliases, attribute calls or transitive dependencies. This syntactic guard cannot stand in for an exhaustive security or effects audit.

No full products.py, configuration-content or runtime-contract audit, executable validation, Docker socket access, database or provider action is claimed.
