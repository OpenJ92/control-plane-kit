Nine tests exercise the pure OCI image-reference language in [products.py](../../../../control-plane-kit-core/src/control_plane_kit_core/products.py). The central distinction is between an execution reference ending in `@sha256:…` and a human reference which may additionally include a tag. One example asserts both exact strings and retained digest/tag descriptor fields; a separate case rejects an empty digest even when `latest` is supplied. These are local value checks, not proof that registry content exists or matches its declared digest.

The constructor rejection table covers a short digest, a different digest algorithm, a registry URL, embedded registry credentials, parent traversal and uppercase repository names, a tag containing a space, and a provenance key containing `token`. A separate credential case checks that one secret canary is absent from `str(exception)`. It does not inspect exception chains, logs or every secret-bearing input. Provenance rejection is based on field-name hints; it is not a scanner for arbitrary sensitive values under otherwise accepted keys.

One two-platform example round-trips through OciImageReferenceCodec and preserves its encoded descriptor. Four negative descriptors exercise an unknown top-level key, missing digest, an incomplete platform object and a forbidden provenance key. Despite the test name mentioning wrong types, this table does not supply a systematic primitive-type matrix. Another test rejects uppercase platform OS text. The platform matrix accepts declared Linux amd64/arm64 and rejects s390x with a message containing its label; it does not contact a runtime or inspect an OCI manifest.

Source context matters when extending these assertions. The codec requires exact image/platform descriptor keys, and the constructor validates lowercase SHA-256 syntax, repository components and optional tag syntax. An empty platform tuple leaves platform choice unconstrained. Platform values are sorted, not deduplicated. Registry syntax has no explicit total host-length check; the 16-field provenance limit is enforced by codec mapping admission, not by the direct constructor's provenance helper. The current negative examples do not prove all advertised bounds, normalization cases or constructor/codec equivalence. Such behavior needs its own assertions if changed.

The final test parses the entire products.py source and rejects eight named import roots plus direct calls spelled `__import__(…)`. This is a finite syntactic boundary check: it neither resolves transitive imports nor proves absence of every possible effect, import alias or dynamic execution mechanism.
