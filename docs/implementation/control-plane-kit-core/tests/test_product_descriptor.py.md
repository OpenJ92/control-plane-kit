Nine tests cover the product-document codec boundary in [products.py](../../../../control-plane-kit-core/src/control_plane_kit_core/products.py). The helper constructs an in-memory container-server product with a pinned image and HTTP provider socket. Its description mentions live acceptance, but this file performs no live acceptance or image acquisition.

The encoding test asserts filename, media type, product equality, byte length, absence of a final newline, top-level schema/product order and the container-server discriminator. It independently applies hashlib.sha256 to the returned bytes and compares that result with content_digest; repeated encoding must return identical bytes. There is no literal golden document spanning every nested field. A second test round-trips the same document through bytes, text and a parsed mapping.

Mapping input is semantic: recursively reversed mapping order still reconstructs the canonical document, including with max_bytes set to its exact encoded length. Text and bytes made from that reversed mapping are rejected as noncanonical. A separate pretty-printed example is also rejected. The actual codec snapshots mapping input, rebuilds values through the product codecs and emits their descriptor order. For bytes/text it compares input and reconstructed canonical encodings; it does not silently normalize their order or whitespace. This is CPK's document encoding contract, not a claim of conformance to an external JSON canonicalization standard.

The escape-budget example includes a quote, backslash, DEL, BMP and non-BMP characters. Mapping admission succeeds at the exact ASCII-escaped byte size and fails one byte below it. The failing error must be at most 128 characters and have neither cause nor context. The snapshot test proves one traversal of the custom root mapping for its valid example. Eight hostile inputs cover a cycle, deep nesting, an oversized sequence, a huge negative integer, infinity, a string subclass, repeated mapping keys and a failing mapping. Each must produce a bounded ProductDescriptorError without the marker, cause or context. These assertions are specific to mapping admission; they do not establish the same disclosure guarantee for every nested decoder or byte/text failure.

Source inspection supplies the budgeting shape: exact primitive types, finite floats, active-container cycle detection, depth and member limits, and accumulated ASCII-escaped widths. The too-many sequence example can exceed its byte budget before the separate member limit, so it does not isolate that guard. The root one-shot fixture does not prove every nested custom mapping or method is visited exactly once. Limits also do not prevent arbitrary user-defined Mapping methods from blocking or doing work before they return.

The remaining rejection examples cover an extra document key, a product class_path escape, malformed JSON, oversized bytes, a wrong schema name and an incomplete replacement product. That last case changes both kind and required fields, so it does not isolate the unknown-kind branch. The fixtures do not attempt exhaustive field, Unicode, recursion or secret-disclosure coverage. Product-descriptor hardening has [its own test companion](test_product_descriptor_hardening.py.md).
