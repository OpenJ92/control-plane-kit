Nine tests follow product values into ordinary application blocks and graph material. The helper declares a digest-pinned image, HTTP provider at container port 8000, LOG_LEVEL, a JSON configuration artifact and an opaque secret-reference environment delivery. ProductInstanceConfiguration.from_contract supplies matching default material. A DockerRuntime is topology data here; these tests do not open Docker or fetch secrets.

The catalogue-instantiation example asserts role ID, provider names, display name and oci-container implementation kind. After compile_topology it checks application family, kind, the literal endpoint `http://hello-blue:8000`, product identity, descriptor digest, image execution reference, public environment, artifact ID and secret reference ID. The endpoint is planned address material, not a listening endpoint or health observation. A separate directly instantiated graph must round-trip through GraphDescriptorCodec.

The configuration mismatch test rejects a wholly empty configuration and one with an extra public environment name, both with a public-environment error. Because public environment is checked first, the empty case does not independently exercise missing artifacts or secret deliveries. Another example changes LOG_LEVEL from info to debug and observes the new graph value. The actual [configuration comparison](../../../../control-plane-kit-core/src/control_plane_kit_core/products.py) checks declared keys: environment names; artifact ID/path/media type/mode; and secret delivery kind/target/intent/policy/binding, plus requirement socket where applicable. It deliberately omits environment values, artifact content and secret reference identity from those respective keys. “Matches exactly” therefore describes these key tuples, not identical configured values or a blanket no-change rule.

The requirement-secret fixture uses an optional, unconnected runtime-control Postgres requirement. Its replacement reference survives on the block and graph requirement socket and through graph encoding, while node-level active secret_deliveries remains empty. It does not test the corresponding connected case. Selected [topology compiler code](../../../../control-plane-kit-core/src/control_plane_kit_core/topology/compiler.py) adds requirement deliveries to the consumer when applying a connection; instantiation only replaces the socket's declared delivery material. Three rejection examples cover missing requirement deliveries, a changed use intent and duplicate requirement/delivery keys despite different references. An unconditional environment-reference delivery may also receive a per-instance reference. These are reference values and declared uses; neither possession of a reference nor graph compilation authorizes resolution.

A traversal-shaped role ID must fail during instantiate_product, before the test calls topology compilation. The final AST check rejects direct calls spelled open or __import__ in products.py; it does not establish transitive purity or rule out attribute/aliased calls. The inspected OciContainerProductImplementation.materialize ignores runtime and constructs graph material; this is not a concrete container interpreter.
