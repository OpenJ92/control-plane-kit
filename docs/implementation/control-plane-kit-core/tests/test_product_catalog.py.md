Seven tests exercise ProductCatalog as a pure collection of product documents indexed by structural product identity. Its helper builds one digest-pinned container-server product with an HTTP provider socket, optional revision/image digest/description and fixed display defaults, then creates document bytes through ProductDescriptorCodec. The fixture neither imports a product implementation nor contacts its registry or starts an HTTP service.

The empty-catalogue example checks that adding returns a populated value while the empty input remains empty, that empty is a left and right merge identity for that example, and that re-adding the same document returns the identical catalogue object. A two-document example checks identity-sorted storage, successful lookup and an explicit UnknownProductIdentity for an absent name. Changing only description under the same product identity creates conflicting document digests; both from_documents and sequential add must reject that conflict. Thus identity equality alone does not permit replacing descriptor content.

The merge example compares two parenthesizations of three non-conflicting singleton catalogues, including equality of their digests. This is one executable associativity example, not a generated proof for every catalogue. The file does not separately test merge conflicts, commutativity, distinct-but-equivalent duplicate documents, or invalid add/merge argument types. The [actual catalogue implementation](../../../../control-plane-kit-core/src/control_plane_kit_core/products.py) keeps the first document for an identity when content digests agree, rejects disagreement, sorts by identity, and implements merge by repeated pure add. This duplicate admission differs from the stricter [identity uniqueness helper](test_product_identity.py.md).

The descriptor example checks the sole top-level `products` key and hello/router order. Reconstructing a catalogue from its products must preserve content bytes and digest. There is no independent expected byte string or SHA-256 oracle here. In source, descriptor reads each document's content as JSON; content serializes the ordered descriptors and content_digest hashes those bytes. The codec-built fixtures are coherent, but the catalogue constructor only checks document types and identity/digest conflicts. It does not independently validate manually supplied document content against its product value; the direct-document limit described in [the reference tests](test_product_reference.py.md) still applies.

A single invalid object must produce ProductCatalogError before any document identity is accessed. The final AST check rejects direct calls named `open` and `__import__` in products.py. It does not scan import declarations, attribute calls, aliases or transitive dependencies, so its broad filesystem/loading test name is not universal I/O evidence. Catalogue content is not a secret-redacted operational projection, authenticated acquisition record or permission to execute a product.

Read depth: full 133-line test/helper and the catalogue class; selected actual identity, document construction/hash/codec and prior image/reference contracts. No full products.py or runtime-contract audit, executable validation, registry lookup, persistence or deployment is claimed.
