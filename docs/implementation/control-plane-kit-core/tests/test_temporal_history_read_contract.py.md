Two tests fix the Core HTTP/projection/MCP correspondence for six temporal collections: activity timeline, open sessions, session plans, session approvals, pending approvals and plan runs. The HTTP identities read.activity and read.sessions intentionally map to projection identities read.activity-timeline and read.open-sessions; consumers must use the explicit binding rather than assuming identical names.

The first test checks exact HTTP paths, READ scope and READ_ONLY safety, then the corresponding projection kind, paged flag and 100-item maximum. It does not explicitly assert the HTTP method, workspace flag or byte limit. The second filters parity bindings to those six operation IDs and compares their exact MCP names; unrelated collections are outside that equality. Both construct real Core contract values, but neither invokes a server, database, cursor codec or streaming transport.

Read the [projection contract](../src/control_plane_kit_core/operations/projections.py.md), selected actual [HTTP route table](../../../../control-plane-kit-core/src/control_plane_kit_core/operations/http.py) and [parity table](../../../../control-plane-kit-core/src/control_plane_kit_core/operations/parity.py) for the represented correspondence. Temporal ordering, changing page membership, tenant authorization and response enforcement belong to other tests/owners. No negative cases are introduced by this file. Full 96-line test read; selected exact route/binding entries checked against previously reviewed projection/MCP contracts. No executable validation was performed.
