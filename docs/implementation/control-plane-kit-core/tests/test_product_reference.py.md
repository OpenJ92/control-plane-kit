Five tests exercise a product reference as the pair of ProductIdentity and ProductDescriptorDigest. The document helper creates one container-server product with an HTTP provider socket, a digest-pinned image, descriptive text and a default runtime contract, then calls ProductDescriptorCodec.encode_document. It is an in-memory fixture; its repository name and HTTP socket do not launch an application, fetch an image or advertise a running endpoint.

The first assertion group checks that ProductReference.from_document copies the document's product identity and content_digest, and produces exactly the two descriptor fields `identity` and `descriptor_sha256`. The catalogue example obtains the same reference through reference_for and checks that `source`, `url` and `registered_at` are absent. Acquisition location and registration history therefore do not become reference fields in this example. It does not exercise duplicate catalogue identities, conflicting documents, missing lookups or persistence.

The codec example round-trips this reference, then separately adds `source_url`, `workspace_id`, `imported_by` and `registered_at`; each must fail with ProductReferenceError mentioning unknown keys. This file does not test missing reference fields, malformed nested identities or every error type. The actual [reference codec and identity owner](../../../../control-plane-kit-core/src/control_plane_kit_core/products.py) enforce their respective exact field sets, with nested identity failures retaining the identity error boundary.

The digest test accepts 64 lowercase hexadecimal characters and rejects a `sha256:` prefix, 63 characters, uppercase hexadecimal and non-digest text. This raw document digest differs from the prefixed OCI image digest covered by [the image-reference tests](test_oci_image_reference.py.md). The expected document digest is read from the fixture's content_digest property; the test supplies no independent golden bytes or independently calculated digest. Source inspection shows that property hashes content bytes and the codec supplies its canonical document encoding. Direct ProductDescriptorDocument construction checks the product/bytes types, not their correspondence; from_document does not independently revalidate that correspondence. The codec-created fixture must not be generalized into a proof that arbitrary manually assembled documents are coherent or authenticated.

The final test parses imports in products.py and rejects six named substrings associated with server, persistence and HTTP ownership. It examines Import/ImportFrom syntax only, not dynamic calls, transitive dependencies or all effect mechanisms. Neither this guard nor a valid reference authorizes execution, verifies a signature, establishes provider ownership or proves registry availability.
