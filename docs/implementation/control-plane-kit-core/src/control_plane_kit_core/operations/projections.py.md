# Operator read projection vocabulary

ReadProjectionContract names an operation, projection kind, response schema and disclosure policy, together with read-service, authorization, workspace and pagination declarations. This is data for consumers, without a callback or store. A REDACTED policy label does not redact a response, READ does not authenticate an actor and READ_ONLY does not itself prevent effects in an implementation.

Construction requires typed kind, policy and service role, with the role fixed to READS, scope fixed to HttpAuthScope.READ and safety fixed to READ_ONLY. Operation/schema identifiers admit nonempty ASCII letters, digits, dots, dashes and underscores without a length cap or required read. prefix. Workspace/paged flags must be actual booleans; workspace=False is admitted even though the canonical factory always sets True. A policy, schema or kind is not checked against the canonical definition for that operation.

Paged values require max_page_size from 1 through 500; unpaged values require None. Both direct construction and descriptor decoding use isinstance(value, int), so True survives as a page size of one while False fails the lower bound. This declaration does not count returned items or encoded bytes. Canonical collection limits are 100 except revision-preparation and revision-attempt pages at 10; details are unpaged. The Operations read-page owner supplies actual request/page admission rather than deriving runtime enforcement from this value.

ReadProjectionSet requires a tuple of contracts, unique operation IDs and kinds, and exactly the canonical operation-ID set. It sorts by operation ID. These checks require complete membership but do not require the canonical association between an ID and kind/schema/policy/flags; swapping distinct kinds or changing other admitted fields need not violate the set constructor. canonical_operator_read_projection_set() supplies the intended associations from the local definition table. Lookup validates the identifier and reports an unknown ID if absent.

Both descriptor decoders use exact key sets; the set decoder requires its fixed kind and a list of member mappings. No aggregate byte bound or universal redaction is added. Enum conversion and unknown-ID errors can retain supplied text, including chained causes. Response schema here is a name; the separate [HTTP owner](../../../../../../control-plane-kit-core/src/control_plane_kit_core/operations/http.py) owns HttpSchemaRef byte-limit declarations.

The [parity owner](../../../../../../control-plane-kit-core/src/control_plane_kit_core/operations/parity.py) maintains explicit HTTP-route/MCP-tool bindings and checks selected structural agreement with its HTTP contract. That is representation consistency, not live adapter execution.
