# Effect-attempt transition language

This owner defines attempt identity, ownership fence, recovery decision, transition and state values, then folds one transition into a state. It performs no database access, clock/ID generation, provider observation, approval or dispatch. A returned SUCCEEDED state describes supplied evidence; it does not establish that an external operation succeeded or that the caller may mutate durable truth.

Identity combines an exact RunId, canonical activity identifier and positive attempt number bounded by PostgreSQL int4. Activity and run strings use their shared ASCII identity grammars. Fence generation uses positive int8 range; both integer fields reject booleans and integer subclasses. Worker and decision IDs allow nonblank UTF-8-encodable text up to 256 characters, excluding NUL. They retain original text rather than trimming it; this is a character bound, not a 256-byte bound or a secret-content filter. The checks call base str methods so hostile overrides cannot disguise invalid contents.

STARTED carries request fingerprint and optional retry lineage, with no outcome or recovery decision. Four direct results—SUCCEEDED, FAILED, UNSUPPORTED and UNCERTAIN—carry only outcome fingerprint beyond identity. RECONCILED carries a same-attempt decision resolving succeeded/failed; ABANDONED requires abandoned resolution. All fingerprints are 64 lowercase hexadecimal characters; their syntax does not authenticate evidence or recompute any preimage.

The first fold requires STARTED and adopts the supplied fence. Later folds require equal identity and exact stored-fence equality before checking duplicate handling. Exact duplicate starts return the same object only while still STARTED. Exact matching direct results and recovery decisions can likewise return the same terminal/uncertain state object; changed evidence or conflicting terminal transitions fail. This is local fold idempotency, not a complete durable replay protocol.

A new direct result requires STARTED. Once UNCERTAIN, an ordinary success/failure cannot resolve it: the fold requires an explicit recovery transition whose decision matches the recorded uncertain fingerprint. The resulting state retains the decision and replaces outcome fingerprint with its evidence fingerprint. State constructors check this local consistency but cannot prove that a prior uncertain event existed; only folding against that prior state makes the comparison.

First attempts forbid prior_attempt. Later attempts require the same run/activity and exactly attempt-1. A new fold with state=None accepts that structural lineage without loading the prior attempt, checking its status or authorizing retry. It also does not advance a lease generation or decide expiry. The actual [Operations fold interpreter](../../../../../../control-plane-kit-operations/src/control_plane_kit_operations/effect_attempt_fold_interpreter.py) separately checks current authority and transition authority, then supplies the historical attempt fence to this fold. The [start interpreter](../../../../../../control-plane-kit-operations/src/control_plane_kit_operations/effect_attempt_start_interpreter.py) records resulting state/events through its own transaction boundary. Those consumers own durable evidence, correlation and authorization beyond this pure language.

Codecs use exact mapping keys and nested constructors; there is no complete serialized-byte bound or general redaction pass. Bounded-text/integer rejection uses fixed messages, including guarded malformed run decoding, but invalid enum decoding preserves ValueError text and cause. Treat typed fingerprints and ID bounds separately from public disclosure policy.
