Six tests exercise immutable realized-projection persistence on real PostgreSQL. Setup installs current schema and truncates workspaces with CASCADE at the configured owning-suite URL, rather than creating a unique schema. This destructive fixture setup belongs only in the disposable Docker package harness. Store/UoW reads are local persistence evidence, not live gateway deployment, key rotation or process restart.

The fixture uses actual Core authored delegation bindings, verifier projection and materialize_delegation_verifiers to construct two graphs with different public verifier material. Their shared authored graph remains unchanged while retained realized digests differ. The small QUFB/QkJC PEM bodies are synthetic framing inputs: DelegationPublicKey validates ASCII/public framing and computes a fingerprint, not actual Ed25519 key parsing here. Absence of PRIVATE KEY in the two descriptors is a selected canary assertion, not a general secret or provider-permission proof.

Semantic replay supplies a different projection ID for the same workspace/source/kind/key and material, expecting the original stored record; changed material under that same semantic identity conflicts. The conflict is an application exception after INSERT ON CONFLICT DO NOTHING, allowing that test transaction to commit the first record. This is sequential store replay, not a concurrency, driver-failure or command-idempotency test.

Other cases check canonical timestamp rejection, cross-workspace authored-source denial, deterministic identity construction plus durable round-trip, and no-commit rollback of workspace/authored/realized rows. The timestamp case ends without committing, so zero rows alone is not instrumentation of pre-write ordering; the [store](../src/control_plane_kit_operations/postgres/graph_store.py.md) independently encodes time before SQL. Identity materialization is not provider observation or approval. No test publishes a desired pointer, validates a completed run or executes an external effect.
