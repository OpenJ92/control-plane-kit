These 12 PostgreSQL tests cover selected journal, claim, run, expiry and error
boundaries of the [lease-recovery interpreter](../src/control_plane_kit_operations/execution_lease_recovery_interpreter.py.md).
They invoke actual services/stores around deliberately constructed or corrupted
history and substituted failures. They do not repeat an external effect, authenticate
an operator, prove every recovery schedule or implement automatic repair.

The inherited [fixture](execution_lease_recovery_fixture.py.md) requires the configured
Docker test database URL, installs schema and truncates workspace-owned truth.
It trusts that URL; this file adds no unique database or isolation check. Commands
use separate real UoWs, while setup mutations and selected snapshot queries use
the fixture's autocommit connection. All fixed IDs/times and the hand-built runtime
plan are test material. Snapshot equality concerns selected claim/event/action/run
columns, not every database object or a globally atomic concurrent observation.

The phase test first executes a real historical recovery with normal lease
observation, then relocates its decision/consequence events and updates the action
payload's event ordinals, action creation time and claim times through direct SQL.
Three fixtures place expired
renewal before start, active renewal after failure, or expired renewal while running.
The active-after-failure case also inserts a failed journal and alters the run.
The new recovery must conflict without sampling lease time or allocating IDs, and
the selected corrupted snapshot must remain unchanged. These are hostile persisted
arrangements, not histories generated by an allowed public lifecycle sequence.

The suffix test constructs three other inconsistent histories: a recovery pair
whose replacement does not reach the current fence, abandonment followed by renewal,
and an opening-event ordinal gap. Its nested add_pair helper directly persists
typed decision/consequence events, not corresponding actions or claim transitions.
Each case expects Conflict before clock/IDs with unchanged snapshot. Intrinsic
record validity does not imply a coherent whole journal, and these rows do not
isolate every possible rejection predicate when more than one inconsistency exists.

The journal test admits three fixtures: active opening-only, ordinary failed,
and a forward uncertainty represented as resolved failure. It rejects ten named
histories covering early effects/start, in-flight or uncertain steps, compensation,
foreign activity, duplicate start, post-terminal success and orphan recovery
consequence. All rejected cases forbid observation/IDs and preserve the selected
snapshot. These are the [shared support](../src/control_plane_kit_operations/_execution_lease_recovery_support.py.md)
eligibility laws exercised through recovery; event labels for resolution or
compensation are manually seeded, not calls to a provider or resolution service.

A separate malformed-journal test changes a persisted event's evidence to a JSON
string. Unlike method-level fault injection, this reaches actual history decoding.
It requires bounded categorical Conflict, canary exclusion and no observation/IDs
or selected-state change. One corrupted evidence shape is not an exhaustive codec
audit or proof that all malformed data is accepted by the schema and caught here.

The request/run/fence matrix has eight selected negatives: active command with
expired claim, expired command with active claim, wrong run state for either form,
queued request, foreign worker, foreign generation and exhausted generation.
Expiry worlds are set to years2000/2099; the generation-limit row uses expired
renewal, not all four command forms. All cases require no IDs and unchanged selected
state, but this matrix alone does not instrument no-clock behavior. A separate
latest-run test uses the fixture's directly seeded newer failed run, not a retry-
service-produced successor, and rejects the stale retained target before IDs.

The equality-expiry test covers all four decisions by calling the real observation
method and replacing its returned observed_at with lease_expires_at and expired
with True. Active renewal must reject without IDs; the other three must complete
with the three supplied IDs. This is service interpretation of a substituted
boundary observation, not an experiment that makes PostgreSQL clock_timestamp
land exactly on an expiry instant. Claim persistence still uses the real stores.

Seven non-expiry rejection cases separately install a failing observation method:
wrong run state, queued request, wrong worker/generation, exhausted generation,
newer run and approval digest drift. They assert Conflict, no ID calls and unchanged
snapshot. Their early-stop evidence is narrower than a statement that all failures
must happen before time observation or that authentication was performed.

Two compare-and-set miss cases replace rotate_request_claim or abandon_request_claim
with a None return. Both expect a categorical Conflict and unchanged snapshot after
all three IDs were consumed. This models the adapter's no-row result, not a real
concurrent compare-and-set loss. The [actual execution store](../../../../control-plane-kit-operations/src/control_plane_kit_operations/postgres/execution.py)
owns the conditional UPDATE; these tests do not reproduce all of its predicates.

Four write-failure stages cover claim rotation, first event, second event and action
for expired renewal. Each wrapper raises a supplied RuntimeError before calling
the selected original method; earlier stages run normally. The identical exception
must escape, and the selected database snapshot must roll back. These are not
after-insert failures at the selected stage, every abandonment write path or
exhaustive adapter-return mismatch tests. Patched class methods are restored in
finally; their temporary replacement is process-global within the test process.

The ID-factory test wraps actual observation, records its return, then raises the
exact injected exception from the ID factory only after that marker. It preserves
the snapshot, supporting observation-before-ID and no durable change on this first
ID failure. It does not test each later ID position or rollback of an external
identifier service's state.

The final method tests a UoW factory exception and a connection commit exception.
Both must escape by identity without selected-state change. CommitFailureConnection
delegates execute, rollback and close to a real connection, but commit raises
before the underlying connection.commit is called. The real
[UoW](../../../../control-plane-kit-operations/src/control_plane_kit_operations/postgres/unit_of_work.py)
therefore rolls back uncommitted work. This does not demonstrate recovery from a
successful server commit with a lost acknowledgment, a process crash, rollback
failure or uncertain durable outcome. No retry is attempted.

Expected errors use the fixture's bounded, chain-free, supplied-canary checks where
the individual method calls safe_error; the seven no-clock cases assert only the
error class and state/call boundaries. Raw injected RuntimeErrors deliberately
retain identity and are not subject to the categorical redaction promise. No
provider/credential/log leakage test, HTTP/MCP parity test or general exception
sanitizer is introduced here.
