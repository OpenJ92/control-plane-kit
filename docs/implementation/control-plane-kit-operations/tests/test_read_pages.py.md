Seventeen pure contract tests exercise the Operations paging language through root exports. They use ordinary in-memory values and selected AST source inspection, not database fixtures, HTTP/MCP transport, credentials or providers. Executable validation belongs to the normal Docker-backed Operations suite. Reading these tests for documentation is not a new green result.

The literal table pins all twenty collection/route/scope/cursor/direction/position profiles and unique routes. It checks collection completeness, not installed route handlers or SQL behavior. The export test's name says exact public objects, but its assertions require a finite name subset in __all__ and non-None attributes; they do not compare each object to its defining module or exhaustively certify root exports. Draft/revision scope entries are exercised by the table, not the same malformed-wire matrix used for the older scope families.

Run scope and decoded run cursors share Core's exact ASCII run-identity grammar: one to 200 characters, an alphanumeric first character, then alphanumerics plus period/underscore/colon/hyphen. Negative values include string subclasses, controls, oversized and badly shaped identifiers. The helper checks bounded str/repr, absent cause/context and selected canaries. Other malformed paging helpers impose a 160-character message cap, no cause/context and optional canary exclusion. These are selected public error contracts, not a general secret scanner.

Five cursor variants round-trip literal wire profiles. Scope/type substitution, missing/extra keys, non-dict Mapping values, format-version types and unsupported values fail. Instrumented hostile Mapping and text values check rejection before their selected interpretation/rendering hooks, especially when an extra field already invalidates the shape. This is not proof against every hostile Python object or dynamic hook.

Boundary rows cover 512-character general identifiers, 128-character delegation identifiers, canonical lowercase delegation shape/purpose, positive exact ordinal values, six-digit UTC timestamp spelling, and epoch 0..signed-int8-max. Epoch wire text deliberately preserves values above JavaScript's exact integer range and rejects numeric wire values, signs, padding, fractions and overflow. The file does not impose an int8 ceiling on ordinal cursors or prove every calendar-invalid instant. Request tests use the ordinary 1..100 profile; the smaller revision-history envelope is owned by its dedicated tests and actual language contract.

Page rows check both exposed and hidden cursor congruence, empty/partial/exact-limit/lookahead behavior, refusal of excess candidates and direct construction, and a continuation from the last exposed rather than hidden item. Map identity/composition examples retain cursor identity and preserve a thrown mapper exception object. Descriptor tests reject non-dict projected items. These values arrive in sorted order in the tests: no monotonicity, uniqueness, item-to-cursor correlation, current database snapshot, deep-copy or provider-proof claim follows.

The final AST test rejects selected import roots and ordinary Name uses of open/eval/exec/__import__ in the paging owner. It does not resolve aliases, dynamic imports, transitive effects or all possible syntax; actual ownership remains a source-review question. No runtime safety claim should be inferred solely from that structural witness.
