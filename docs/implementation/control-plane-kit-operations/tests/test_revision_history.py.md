These twelve real-store tests distinguish revision association, saved-source attribution and historical advancement. They reuse RevisionHistoryFixture and existing preparation commands, not another history implementation. Source-only, target-only and combined sessions remain visible and deduplicate; request presence and attempt presence are independent. Each attempt must qualify its own target plan rather than inherit membership from an unrelated sibling plan in the same session.

Tenant tests use colliding draft identities in separate workspaces, reject a foreign plan through typed admission, then deliberately change retained plan coordinates through SQL to check read-side exclusion. New revisions have no recorded associations. Whole/fractional timestamps and nullable session close times preserve valid saved attribution. Matching target graphs with another source revision stay visible but have unavailable provenance; mismatched saved plan fences likewise do not become saved merely because the session/start commitment is valid.

Malformed/missing/oversized source metadata or start evidence yields unavailable attribution without repair or canary disclosure. Selected history-table snapshots remain unchanged around relevant reads. Every recorded run status remains visible without inventing advancement or an uncertainty field. A directly SQL-tombstoned referenced draft's old history stays readable; that is a retained-state fixture, not permission for the normal delete command to bypass its reference guard. Retry identity is checked against the stored predecessor, including rejection after deliberate attempt-number corruption.

Direct fixture inserts and SQL corruption are test setup, not operational procedures. add_attempt persists typed historical relationships and claims no provider execution; neither a successful run label nor association proves a live outcome. Snapshot comparisons cover the fixture's eight named history tables, not all database or provider state. The fixture trusts its configured database URL; the owning Operations test.sh supplies disposable Docker isolation. No tests, database actions or provider calls were executed for this note.
