This file checks Operations factory/adapter composition for select/delete and the operator overview's draft attribution. It directly invokes services.handle with CatalogueRequest values shaped as HTTP path/payload or MCP arguments; it does not launch HTTP/MCP processes or authenticate real credentials. The shared [selection fixture](draft_selection_fixture.py.md) still performs real PostgreSQL setup before individual request-level forbidden-UoW checks.

Actual cpk_server_services composes catalogue and read services with unrelated command services disabled. The first HTTP call and same-key MCP call return identical selection/deletion results and one durable action per command. Payload actor_id/actor_scopes cannot replace the trusted principal's actor. Deletion's setup restores the legacy desired pointer first: the test does not bypass the selected-revision retention rule through the public delete route.

For both surfaces, absent, foreign-workspace or insufficient-scope principals are rejected before a forbidden command service/read transaction. Forged scope fields on the closed overview request yield 400 before transaction entry. These assertions prove adapter trust-boundary placement, not credential issuance or server middleware. Nine malformed/stale command cases compare status, bounded error descriptor equality, selected secret-marker absence and unchanged fixture truth. Required pointer keys, exact revision/generation types, stale fences and overlong idempotency key are represented; this is not an exhaustive input schema validator.

Overview distinguishes legacy no-draft from an old selected revision plus a newer head, preserving unrelated top-level/history shape. It omits submitted title and graph bodies. An invalid cursor kind is rejected; a test-seeded tombstoned or malformed mapped header yields unavailable with no partial draft coordinates and no repair. The last test hooks a real SQL execution to commit a revision through another UoW after the header query, then requires the changed anchor to make the first response unavailable; a fresh overview returns selected revision one/head two. This is a deterministic interleaving, not an atomic cross-query snapshot or thread-race proof.
