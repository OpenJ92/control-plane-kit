These four credential-free value tests own the revision-history paging envelope, not the semantic validity of every history row. They exercise RevisionReadScope, collection-specific TemporalReadCursor, ReadPageRequest and ReadPage directly without a database fixture. Repository policy still runs executable validation through the owning Docker Operations suite, not host Python; no execution was performed for this documentation.

Scope/cursor cases reject malformed, control-bearing, overlong and wrong-type identifiers; revision must be a positive signed-64-bit integer, not bool. Maximum-width Unicode IDs remain valid. Cursors round-trip and cannot be reused across workspace, draft, revision or collection; missing/extra scope fields fail. History page limits one through ten are admitted at their endpoints, while zero/bool/eleven/hundred fail; the unrelated activity-session collection still admits its existing hundred limit.

The lookahead test proves the continuation cursor comes from the last exposed item, not the hidden candidate, and that hidden candidates still require the exact scope. It does not prove database ordering or discover duplicate semantic rows; those belong to the store and pagination tests.

The descriptor test constructs maximum-width, live-shaped dictionaries for ten exposed attempts plus lookahead. ASCII-escaped compact JSON exceeds 500,000 bytes but stays within the 1 MiB cap. A much larger unexpected dictionary value is rejected by descriptor size. The synthetic rows are encoding witnesses, not evidence of real approvals, attempts, graph transitions or a schema validator for arbitrary item dictionaries; ReadPage enforces envelope/cursor/count/encoding constraints while the history store owns row semantics.
