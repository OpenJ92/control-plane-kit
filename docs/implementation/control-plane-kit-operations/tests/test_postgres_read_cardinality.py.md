Three test methods maintain a finite source-level inventory of PostgreSQL fetchall call sites and selected rotation bounds. The discovery helper is invoked by the inventory test, not collected as a fourth test. This file reads Python/TOML source and imported value/schema contracts; it opens no database or provider connection. Executable validation belongs to the normal Docker-backed Operations suite.

_FetchallVisitor recursively records attribute calls spelled fetchall under named class/function/async-function scopes. It refuses module-level calls and calls inside lambdas. _discover scans postgres Python files and assigns qualified selector names; multiple calls in one selector receive ordinal occurrences ordered by source line. Those identities avoid literal line numbers in the inventory, but reordering/adding calls can still change occurrence meaning. The visitor does not prove the receiver is a database cursor or discover aliases, iteration, fetchone/fetchmany, dynamic calls or reads outside postgres.

The committed policy expects 64 distinct discovered identities, three repeated selectors each with occurrences 1/2, and selected exact module identities. The TOML parser closes header/version/row keys, module/selector spelling, categories, consumer kind and occurrence continuity; sql and consumer must be nonempty strings and a short list of generic consumer labels is rejected. The parser does not resolve consumer references or verify that prose describes actual SQL. Duplicate/gapped identities and selected malformed values are tested with synthetic TOML strings.

The final test requires inventory identities to equal discovered identities and pins category counts: 17 public-paged, 7 fixed-cardinality, 2 closed-finite, 24 internal-complete and 14 exact-verifier. public-unbounded is recognized by the parser but absent from the expected count map. This is an accountability map for the selected fetchall syntax, not a universal guarantee that public reads are bounded or that every listed internal complete read is safe at arbitrary scale. SQL text, actual consumers, query plans, result bytes and runtime memory remain consequential source/design review responsibilities.

The closed-finite test traverses the current _LEGAL rotation status graph, rejects cycles/dead ends and requires terminal reachability. It also scans ordinary source calls to _transition/add_transition, pins their owning method and line order, and checks an if containing _LEGAL plus a raise exists in the expected helper. Actual _advance_locked calls _transition before compare-and-set and transition insertion. The AST witness is not a full control/data-flow proof, concurrent execution test or protection against arbitrary direct SQL writers.

Selected schema-contract assertions pin rotation transition version increment/uniqueness and the overlap/retirement deployment phase vocabulary plus primary key. Together with the current acyclic legal service path these support the documented finite collections; they do not install/inspect PostgreSQL here, validate every retained row or prove provider lifecycle completion. The imported transition graph and schema remain the respective owners, not a parallel state machine implemented by this test.

Full 453-line test/helpers were read; selected actual inventory entries, _LEGAL/transition/writer path and schema declarations were checked with retained [rotation owner](../src/control_plane_kit_operations/gateway_key_rotations.py.md) and [paging language](../src/control_plane_kit_operations/read_pages.py.md) context. The 519-line cardinality inventory was sampled, not audited entry-by-entry. No tests/imports/Docker/database/provider actions or source changes accompanied this companion.
