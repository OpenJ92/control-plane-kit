Fourteen real-Postgres methods exercise saved-preparation association admission and retained-row validation through existing services/stores. SavedPreparationFixture inherits draft selection/catalogue setup: it trusts the suite database URL, creates a unique schema, uses that search path for its units of work and drops only that schema during cleanup. Graph products/runtime declarations are authored data, not provider launches. Use the established Docker-backed Operations suite; the fixture is not permission to point these SQL-corruption tests at live data.

Admission tests require one exact four-field association per session, allow different sessions to share a revision, check tenant-scoped lookup and database membership constraints, and inject an exception after the actual source INSERT to prove transaction rollback of selected durable truth. An admission-stop case then creates a fresh program instance and resumes against persisted source truth without duplicate writes. Its physical-restart name does not mean a process, database or host was restarted. Two threads synchronize before identical preparation and require one result/source/plan; the barrier and inherited UoW lock/statement timeouts are bounded, but the executor wait is not a universal whole-test timeout.

Replay remains the same after draft-head, selected desired graph, session closure and product-status changes. False/missing sources must reject replay and current-schema verification without repairing compared tables. Further direct SQL cases cover source-on-inline sessions, empty candidate session ID, orphan/unknown saved metadata, changed commitment/fingerprint/graph references, oversized metadata, and a bad candidate beyond the first 64-row batch. Dropping the source relation simulates an older/incompatible schema: installation must refuse without recreating it. These are deliberate fixture mutations, not supported operator repair workflows.

The complete-erasure test explicitly establishes the limit: deleting the association and all saved metadata leaves no retained origin for this validator to discover; installation succeeds without modifying the compared truth. Validation is not tamper-proof reconstruction or provider evidence. Snapshot helpers cover their declared table set, not every database or external object. Tests of current-data refusal are not general migration, concurrent tampering or cryptographic-integrity proofs.
