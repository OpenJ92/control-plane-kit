Five tests exercise actual workspace/graph stores and UoW persistence. Setup requires CPK_OPERATIONS_TEST_DATABASE_URL, installs schema and truncates workspaces with CASCADE; it is not a unique-schema fixture. The owning Docker-backed suite must supply disposable database isolation. Fresh connection/UoW reads prove transaction persistence, not process recovery. Fixture DockerRuntime/product values and OCI references do not launch or contact providers.

The first case stores a running lifecycle label plus current/desired graph pointers and reads them back. Running is assigned test data, not observed runtime health. Graph round-trip checks the full typed descriptor, microsecond creation time and highest workspace version across two records. Product construction uses actual Core instantiation/compilation, not a substitute codec, but does not prove all possible graph semantics.

Malformed timestamp rejection checks the fixed UTC message and zero retained graph rows after a UoW with no commit. Source independently places timestamp encoding before INSERT; the test does not instrument SQL to prove every preceding access is absent. The version/CAS case calculates the next version in one workspace, makes a stale expected-current source return None, then advances to the exact desired lineage using all current/desired projection and generation inputs. Despite the workspace-scoped test name, this case creates only one workspace; it is not a cross-tenant matrix or concurrent allocation/CAS schedule.

The final no-commit case leaves both workspace and graph tables empty, proving shared rollback on UoW exit. It is not a database-crash or late-write exception experiment. The row-count helper admits only the two named tables; these tests do not assert all-table or external-resource equality. They bypass application auth, sessions, approval and run evidence deliberately to test storage, and cannot justify bypassing those owners in capstone execution.
