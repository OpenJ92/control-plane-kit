Three methods bind the large-read route matrix to Operations paging profiles, compare direct/read-adapter projections over PostgreSQL fixtures, and check workspace denial before UoW acquisition. These are package-owned composition tests, not actual HTTP/MCP serving, credential verification, provider observation or deployment execution.

The literal matrix covers 18 routes/collections and 17 direct methods because draft catalogue and revision routes share one method. Two revision preparation/attempt collections, with their smaller page cap, are deliberately delegated to test_revision_history_pages; union with those two must equal the twenty current profiles. Callable method and literal inventory checks establish wiring expectations, not the behavior of every route branch or all possible policies.

_seeded requires the configured package database URL and creates a UUID-named schema on an autocommit administration connection. It installs the schema, seeds selected_count=201 history/metadata values, then adds 201 catalogue drafts and 200 further revisions of one draft through actual stores under a workspace lock. All catalogued graph values are synthetic empty topologies. A finally block restores public, drops that schema CASCADE and closes administration even if setup/yield fails; cleanup errors are not separately normalized here. Cleanup calls are sequential: if RESET or DROP raises, later DROP/close calls can be skipped. New reader connections set that search_path and use ordinary UoWs. This is schema isolation inside the configured test database, not authorization to use unrelated data or a host fallback.

Parity uses a fixed clock and all-scope typed fixture principals. For each route it obtains a direct page and independently obtains HTTP/MCP-shaped responses, then repeats once with each returned cursor. First responses must have a continuation and both protocol-shaped mappings must exactly equal the direct descriptor on each call. The test does not request the final 201st item, assert full traversal/no-duplicate coverage, or establish a shared snapshot across those separate transactions. Broader collection traversal belongs to other owners. No live socket, server process or network authentication is involved.

Selected first-page canaries intentionally preserve opaque provider endpoint/credential-reference/prefix handles and registered secret reference IDs. Ingress token/generated-secret references and delegation private-key references/public PEM material must be absent from selected collection representations. A secret:// string is therefore not universally forbidden: a reference handle is distinct from resolved secret bytes, and permitted reference disclosure is projection-specific. These assertions are not a complete arbitrary-payload redaction audit or proof of custody/remote authority.

The denial method requires no database. Synthetic handles plus a foreign-workspace principal and malformed cursor yield the exact fixed 403 message for every route on both adapter surfaces, with no UoW factory call, no cause/context and no selected workspace/token canaries in repr. This observes actual adapter authorization/error precedence over that malformed cursor, not an instrumented decoder or a complete service-role/scope revocation matrix.

Those fixtures directly seed synthetic durable rows, not execute the corresponding control-plane workflows.
