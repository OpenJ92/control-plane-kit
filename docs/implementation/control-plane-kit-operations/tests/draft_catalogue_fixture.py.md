This setup-only mixin supplies real Postgres stores, catalogue commands and local Operations adapters to draft tests and their descendants. It requires the owning suite's database URL, creates a UUID-named schema, installs the schema there and registers cleanup to drop that schema before closing the connection. UoW connections use the schema search path plus five-second lock and ten-second statement timeouts; the original autocommit setup/snapshot connection is not given those timeouts. This isolates fixture namespaces, not the safety of an arbitrary supplied database URL. Execution belongs to the established Docker-backed Operations suite.

Setup creates two workspaces with empty authored current/desired graphs, registers a synthetic inline product only in workspace-a and opens one operation session per workspace. Product/image/DockerRuntime values are declarations; no image pull, container deployment or provider health is established. graph compiles an app instance against those values. create/revise helpers use actual command constructors and services with fixed time and UUID identities; the fixture is not a second catalogue state machine.

principal constructs an already authenticated-looking Core principal with a selected workspace and, by default, all PolicyScope members. It does not verify credentials. read builds HTTP-shaped path parameters or MCP-shaped payload coordinates and directly calls CpkServerReadService.handle. planning_adapter constructs the real planning service. These are protocol-shape composition helpers, not live transports. Route/module/callable checks and a narrow missing-keyword TypeError conversion provide assertions for absent historical interfaces; they do not make every possible missing dependency an apparatus-free red.

rows uses quoted table identifiers and deterministic JSON ordering. catalogue_truth and runtime_truth enumerate specific durable tables for equality comparisons; runtime_truth is a database snapshot helper, not provider inspection. Neither includes every later relation, such as saved-preparation sources. Tests requiring additional truth must name it explicitly. Drop-schema cleanup is fixture-owned and does not authorize production cleanup or repair.

Full 212-line fixture read with [draft selection](draft_selection_fixture.py.md), [saved preparation](saved_preparation_fixture.py.md), selected actual adapter/command/UoW context and their fully read saved-preparation test consumers. No executable validation, database or provider access; not a complete catalogue-service audit.
