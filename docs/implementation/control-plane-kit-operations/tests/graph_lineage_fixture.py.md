Two small helpers seed empty authored graphs, optionally with identity-realized projections, for tests needing valid stored lineage coordinates. They construct prerequisites; they do not assert deployment, approval, execution, provider observation or graph advancement. The workspace must already exist, and callers own connection/UoW, schema, commit/rollback and cleanup. There is no authorization or disposable-database admission here.

`seed_authored_graphs` directly inserts one cpk_graph_versions row per supplied ID, encodes an empty DeploymentGraph and assigns versions starting at 1, a default operator-a creator and deterministic August timestamps. It returns None and creates no realized projections or workspace pointers. It bypasses the GraphVersionRecord/store write path while using the Core descriptor codec and database constraints. Current repository test search finds no caller of this helper; that is not authority to remove it.

`seed_identity_graphs` instead creates each authored GraphVersionRecord through from_graph, saves it through stores.graphs, asks stores.realized_graphs.identity_for_authored for its projection, saves that projection and returns an authored-ID to projection-ID dictionary. [Actual graph stores](../src/control_plane_kit_operations/postgres/graph_store.py.md) either load the existing identity projection or derive it from the authored record. The [record constructor](../../../../control-plane-kit-operations/src/control_plane_kit_operations/records.py) encodes identity kind/key, canonical descriptor and a digest-derived projection ID; this is executable-material identity, not evidence that a runtime realizes the graph. The helper does not select current/desired workspace pointers, plan work or advance them.

These are fixed small-fixture conveniences, not general graph importers or idempotent services. Both restart version numbering on every call and perform authored INSERTs, so existing IDs/versions may conflict. Neither validates the input collection as an exact tuple nor supplies a count bound or batch transaction. Their timestamps put the version into the seconds field: at version 60, direct datetime construction or the store's canonical timestamp encoder rejects the value rather than advancing to another minute. Failure can leave earlier writes committed if the caller uses autocommit. An empty ID collection performs no graph writes and the identity helper returns an empty dictionary.

The identity helper ignores save's returned projection record and returns the ID from identity_for_authored. The underlying projection store may reuse equivalent persisted material; this helper adds no independent reconciliation or concurrency guarantee. In the ordinary fresh fixture path, identity_for_authored derives the deterministic identity from the newly inserted authored record. Do not generalize that setup into approval, ownership, physical-resource identity or replay guarantees.

Consumers include approval/lifecycle, temporal/ordinal paging and lease-recovery/compensation fixtures, plus the [large-read fixture](large_read_history_fixture.py.md). Selected approval and ordinal callers create workspace truth first, call this helper within a UoW and explicitly commit; other callers retain their own transaction choices. The companion does not re-audit all consuming test laws or endorse recovery/provider execution.
