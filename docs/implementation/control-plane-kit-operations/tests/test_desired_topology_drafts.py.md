These three test classes exercise real Operations catalogue services/stores and read adapters through [DraftCatalogueFixture](./draft_catalogue_fixture.py.md). The fixture owns an isolated schema in the owning Docker suite's PostgreSQL, current-schema installation, synthetic products/graphs/principals and selected-table snapshots. It does not start workloads or prove external authentication/provider behavior. Interface/relation assertions retain their historical target-red role; arbitrary import/setup failures are not made semantic evidence.

Command tests prove two drafts and retained prior revisions stay independent, coordinate-only actions correlate with graphs, and selected runtime-truth tables do not change. Title bounds, encodable-but-invalid graphs, workspace product availability/revocation, missing edit scope and foreign-session admission are checked. Exact create/revise replay survives later head changes, product revocation and session closure without new IDs; changed intent conflicts. Mutated action payloads test missing/extra fields, malformed revision types, overbound/missing draft IDs and mismatched graph/revision coordinates before allocation. The payload corruption is issue-owned test setup, not a repair API.

Two worker tests use actual separate units of work: distinct revision commands against one expected head have one winner, while identical creates return one durable revision. A ten-second barrier starts each competition; pool.map and context shutdown are not an independent overall completion deadline. Patching add_action to fail after earlier catalogue writes proves rollback and permits a later ordinary command to succeed. These are in-process database transaction tests, not physical restart or provider retry evidence.

Redaction checks a synthetic api_token marker through revision detail, result and action reads, plus a fixed overbound graph error. They do not prove arbitrary strings are scrubbed or that the stored graph descriptor contains no submitted metadata. The read owner owns projection policy; the [catalogue owner](../src/control_plane_kit_operations/desired_topology_drafts.py.md) retains authored intent.

Schema tests require current catalogue relations, exact installer reentry without changing relation identities or saved-only graphs, cross-workspace graph FK rejection and duplicate revision rejection. Adding a foreign column or corrupting a saved-only graph must make installation require reset without repairing/deleting the retained data. The test's direct DDL/DML is confined to its isolated fixture; “reset required” is not permission to reset a real database.

Read tests cover ascending time/ID pages despite differing creation order, revision seek pages, collection/workspace/draft cursor binding, invalid limits and foreign-workspace detail rejection. Calls pass through actual application read adapters, not network HTTP/MCP servers. Separate selection/deletion and saved-preparation suites own those later command contracts; this file is not their complete evidence.

Full 383-line file read, full command/store and selected schema constraints checked, with the previously full-read shared fixture/read-page/projection contracts. No tests, database, Docker or provider actions were run. Executable validation belongs only to the unmodified Operations Docker-backed suite when separately authorized.
