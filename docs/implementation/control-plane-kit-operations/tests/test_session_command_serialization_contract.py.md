Seven source/JSON contract tests check the [session-command serialization manifest](../session-command-serialization.json.md). They do not connect to PostgreSQL or exercise commands, locks, approval, effects, rollback or concurrent transactions. Executable validation belongs to the established Docker-backed Operations suite; none was run for this note.

setUpClass parses the manifest once. The first test requires the exact five role names in order, ordinals 1..5, uniqueness and truthy mechanism/law descriptions. Another pins the literal set of 21 unique command names and truthy service/writer/source/session-rule fields. These checks do not deeply validate field types, reject every extra document key or verify schema_version/contract_id. Multiple command names can legitimately share a writer, such as close/cancel, so the command count is not a distinct implementation count.

Writer discovery scans src Python files with AST, collecting ordinary FunctionDef bodies containing calls named add_action. Class names and relative file paths form writer identities. Calls are sorted by source line and column; attribute receivers are not resolved. Several known helper names are normalized to get_session_for_update. The discovered writer set must equal the manifest's declared writer set. That catches this selected source pattern, not writes through aliases, raw SQL, arbitrary helper indirection or all alternate/async entry shapes. Nested code included by ast.walk and lexical source order are not a control-flow model.

For non-start commands, the first named identity lock must precede the first normalized session lock, which must precede action-ordinal allocation. Recovery/retry commands additionally require session lock before lease observation, lease observation before event-ordinal allocation, and event before action ordinal. Missing names fail lookup. This test does not generically verify every workspace/dependent lock, advisory-lock key, transaction lifetime or which branch actually executes those calls. Session start is intentionally excluded because the row does not exist yet; its actual pre-row key and caller-owned noncommitting writer are separate source/behavioral responsibilities.

A rotation-specific test uses string positions in the shared projection source: nonlocking locator before workspace FOR UPDATE before rotation FOR UPDATE. Another checks each manifest role list is unique, an ordered subset of the five roles, starts with command-identity and ends with action-ordinal, with session-lifecycle present except for start. The former is a finite textual witness; the latter validates the declaration, not the runtime acquisition sequence. Neither proves deadlock freedom or every writer's behavior under concurrency.

The final test requires exactly six outcome-law names and truthy descriptions. It does not execute identical replay, changed-intent conflict, competing commands, terminal fencing/replay or commit/rollback. In particular, the actual workflow may return the same retained action alongside current session truth and replayed=True; this test is not a frozen whole-response comparison. Owning command tests and inspected source remain authoritative for those semantics.
