# Persisted derivation replay

Historical-plan fixtures deliberately store original plan/action records through real stores, distinguishing reproduction of historical pending intent from positive runtime execution. The existing helper now accepts exact registered products for image pairs; its old default is unchanged.

Two #2017 targets preserve recorded V1 and new ingress plans, profiles, literal request fingerprints and payload bytes after pointer movement/session close, using reconstructed services and no new allocation. Fresh selection for the same image pair is independently asserted to choose the new profile. Plan/profile substitutions fail without publishing additional records. This strengthens the existing strict replay and evidence-binding laws; it does not authorize rewriting approvals, runs or uncertain outcomes.

Targets first fail on the missing enum. Deeper PostgreSQL replay assertions must later pass through the owning Docker gate. No DDL/data migration, external credentials or provider effects are involved.
