This owner contains three different forms of evidence, which should not be conflated. Five SQL-shape tests call real store page methods with a recording connection returning no rows. They inspect bounded keyset query fragments, parameterized parent/workspace membership and aware datetime cursor parameters, including limit+1 lookahead. Single-query assertions cover approval joins, pending-approval anti-joins and plan/run membership. These tests do not execute SQL or establish query-plan performance, row decoding or database isolation.

Two thin-detail tests check that session/plan/approval detail signatures have no page-limit parameter, then exercise only session_detail with minimal fake stores. The returned session descriptor contains no embedded action/plan/approval/run/event collections. That is a concrete narrow projection witness, not proof that all detail methods have no transitive reads or that fake workspace lookup grants authorization.

Three real-Postgres membership tests use separate reader/writer connections and committed changes between reads. Closing a session removes it from later open-session pages; inserting identities on either side of a cursor admits only later keys during continuation but both on a fresh traversal; deciding an approval removes it from later pending pages. Expected results demonstrate live statement membership without duplication for those scenarios, not a frozen multi-page snapshot or a simultaneous race test. Setup inserts graph/plan/approval truth directly; no operator or provider execution is implied.

The database-backed class trusts CPK_OPERATIONS_TEST_DATABASE_URL, installs schema and truncates cpk_workspaces CASCADE before seeding. It does not use the unique-schema fixture or verify URL ownership. Teardown closes its connection; isolation belongs to the established Docker Operations suite. Even the credential-free shape/detail tests must use that owning suite under repository validation policy. No executable or database validation was performed for this companion.
