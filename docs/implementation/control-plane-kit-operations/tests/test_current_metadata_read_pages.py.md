Fifteen methods separate four kinds of evidence for seven current-metadata collections: observations, runtime authorities/deliveries, ingress authorities, secret providers/references and delegation keys. These are Operations records, not live provider inventory. The file combines static contract/recording-SQL checks, real Postgres pagination, admission-order probes and direct adapter parity; those layers are not interchangeable.

The eight contract methods pin Core's paged/max100 advertisement, exclusive ascending identity seeks and limit+1 parameters, observation DISTINCT ON selection, delegation's complete purpose/issuer/key tuple, selected unique indexes/constraints, facade signature and owner selector spelling, retired wrapper absence and selected module-inventory exports. Recording connections return no rows: SQL fragments and parameter assertions are not PostgreSQL execution/planner/cost evidence. Source-string and inventory checks are finite migration witnesses, not a whole-call-graph ownership proof.

Four database methods require CPK_OPERATIONS_TEST_DATABASE_URL. Each creates a UUID-named schema on an autocommit connection, sets search_path, installs the schema and inserts one workspace; tearDown restores public, drops that exact schema CASCADE and closes. Isolation is per schema here, not package-wide TRUNCATE, and the fixture trusts its configured connection. It adds no special cleanup if setUp fails partway. Only the established Docker-backed package suite may execute it under the governing validation policy.

The first database case seeds three rows per collection and traverses pages of two, checking expected order and no duplicates/skips. Latest observations choose one record per subject; delegation keys seek a compound identity; authority/provider pages filter active records. Subsequent cases deliberately commit sequential changes between page calls: insertion behind the cursor appears only on fresh traversal, insertion ahead appears on the next page, revocation affects each new page independently, and a newer observation behind the cursor does not rewrite an already returned page. These are live database membership examples, not simultaneous transaction races or snapshot isolation. The traversal helper loops until next_cursor is None without a separate iteration/deadline guard.

Seeded Docker/Cloudflare authority values, secret references and public-key text are synthetic local records. Store registration here does not resolve secrets, contact providers, prove key possession, mount sockets or validate remote resource ownership. One workspace and selected identities are used; this is not a complete cross-tenant, key-collation or status-transition matrix.

Two admission-order tests supply an HTTP-shaped malformed cursor and a factory that records/raises if acquired. Authorized malformed input produces 400 before a UoW; an unauthorized principal produces 403 before that factory and before the malformed-cursor error. The cursor is a malformed dict, not an instrumented hostile decoder, so the test observes status precedence rather than every internal decode instruction. Principals are typed fixture objects, not network authentication evidence.

The final parity method uses actual CpkServerReadService and projection composition with fake workspace/two-page stores, a no-op UoW and a fixed clock. All seven routes return equal HTTP/MCP-shaped first and second page mappings; the fake checks collection, workspace and the exact returned continuation. This proves adapter composition over those values, not actual HTTP/MCP serving, database transactions or deep redaction of every possible stored field. Synthetic private-looking inputs are present, but this method has no separate comprehensive forbidden-value scan.
