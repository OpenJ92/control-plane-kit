Six tests check selected distribution, static import, descriptive foundation and export boundaries. They read package source/metadata and construct a pure bootstrap value; this file does not create a database fixture or provider client. Executable validation still belongs to the established Docker-backed Operations suite, not a host import or alternate test command.

Metadata assertions require the Operations distribution name, exact declared Core/psycopg lower-bound dependency list and no optional dependencies or console scripts. The foundation descriptor must expose the architectural Core edge, current Core deployment-stage enumeration and selected owner/exclusion labels. The historical future_owners label is checked for membership, not treated as a completion ledger. These tests are not a built-wheel content audit or proof across every Python/dependency version allowed by metadata.

_source_imports parses every package .py file with ast and records roots of ordinary Import/ImportFrom statements, including statements inside functions or conditions. It rejects named process/framework/provider, legacy-package and subprocess roots, requires Core, and confines detected psycopg imports to postgres. This is a source-syntax check: it does not execute conditional paths, resolve dynamic imports, inspect transitive dependencies or prove all external effects impossible. Relative imports and import mechanism details remain source review concerns, not a second architectural authority.

The bootstrap test allows Docker as a process capability, checks its descriptor and scans repr/descriptor for selected authority/secret/address words. It proves that one configuration's representation does not contain those fields, not that Docker exists or that all arbitrary strings are redacted. The secret-provider test checks five public names are members of __all__; it does not independently instantiate each type, validate behavior or certify the complete export inventory.
