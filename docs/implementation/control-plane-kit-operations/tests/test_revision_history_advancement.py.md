These eight tests read historical receipts produced by the actual CurrentGraphAdvancementCommandService. They instantiate the existing advancement test fixture for setup and register its teardown, rather than inheriting and recollecting its tests. The fixture seeds a succeeded run and step events directly; actual graph-advancement acceptance then produces the receipt pair. This is real Operations persistence/command composition, not proof that a provider executed the seeded activities.

A succeeded run alone has none-recorded advancement and unavailable saved-source provenance. A real accepted pair projects exact event/action IDs, destination digest and canonical UTC microseconds; later changes to current graph, worker claim or removal of the claim do not erase historical acceptance. That persistence of history does not grant current execution authority.

Missing either half or duplicate candidates on either side yield unavailable evidence. Deliberate SQL mutations exercise mismatched request, plan, run, event, transition coordinates, digest, revision, claim generation and time, plus oversized payloads. Reads leave the inspected mutated payloads untouched and do not return the private canary. These are selected no-repair checks, not an exhaustive all-table immutability audit. The index test inspects actual pg_indexes definitions for receipt lookup keys/predicates; it does not prove the planner always uses those indexes or establish a performance bound.

Safety matters in the reused fixture: it trusts CPK_OPERATIONS_TEST_DATABASE_URL, installs schema, and executes TRUNCATE cpk_workspaces CASCADE in that configured database. It does not create the catalogue fixture's unique per-test schema or independently verify database ownership. Use only the owning Docker Operations test.sh and its disposable database; never run this fixture against an arbitrary host/shared URL. No executable validation or database mutation was performed for this companion.
