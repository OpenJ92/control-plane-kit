These tests own catalogue selection and tombstone transaction laws through [DraftSelectionFixture](draft_selection_fixture.py.md), actual catalogue/planning services and PostgreSQL. Synthetic graphs/principals remain local values. Selection changes desired intent; neither identity projection nor unchanged effect-table snapshots prove a deployed provider topology. The inherited unique-schema fixture and its SQL corruption/setup helpers must remain confined to the owning Docker suite.

Selection preserves the exact old revision without graph copying, keeps current lineage unchanged and is not moved by a later draft revision. Each expected desired graph/projection/generation coordinate fences admission; repeated same-graph selection under a new key increments generation without duplicating its identity projection. Restoring the prior graph still leaves an ABA generation conflict. Overflow, negative, bool and string generations fail before recorded writes. Stored graph semantics, workspace product availability and revocation are rechecked on fresh selection, including direct test-seeded invalid descriptors and foreign-workspace catalogue rows.

Unused deletion tombstones only the header plus its action, retains prior revisions and read access, and blocks later new select/revise/delete commands. Current/desired pointers and either plan graph side protect even older revisions; planned, cancelled and superseded plans all retain references in the tested cases. Status changes in that matrix are direct fixture SQL after actual plan creation. The index test checks separate leading btree definitions for plan base/desired graph lookup; it does not measure query plans or performance.

Completed selection/deletion replay survives later head, pointer, product, tombstone and session changes. It returns exact historical results before ID allocation, with no recorded INSERT/UPDATE/DELETE or selected-table drift; changed intent conflicts. Corrupted action coordinates, projection/generation, tombstone attribution and extra/missing fields fail with bounded errors, without repair. A real duplicate action primary key after preceding writes proves atomic rollback of selection/projection or tombstone.

Concurrency tests inspect advisory-key/session/workspace/draft lock order, race two distinct compare-and-set commands and force select/delete overlap in both orders. Another pair demonstrates planning holds the shared workspace lock and deletion cannot bypass retained plan references. In the delete-first branch, the waiting planner has deliberately stale desired lineage; its rejection is not proof that planning directly checks every tombstone. Event/barrier waits are five seconds and selected result waits ten; pool.map/shutdown do not establish a universal deadline. The fixture's signal is before a lock attempt, not proof of acquisition. These are controlled in-process real-DB schedules, not process crash or exhaustive isolation proofs.
