RevisionHistoryFixture supplies setup and navigation for the revision-history tests, not a replacement relation implementation. It inherits the saved-preparation/draft-selection/catalogue fixtures and asserts that the revision scope, two history collections and store owner exist. Its request factory defaults to ten items and binds workspace/draft/revision; tests may supply smaller limits and cursors.

page opens a caller UnitOfWork and invokes the actual revision-history store. service_page composes InstanceReadService from the real workspace, graph, draft and history stores. wire_page and detail use the inherited CpkServerReadService adapter helper with fixture principals and HTTP/MCP-labelled request shapes; they do not launch a server or exercise a real transport or credential verifier. plan loads the prepared plan through the actual history store, while clone_plan deliberately copies a record with caller-selected identity/changes and commits it as fixture data.

add_attempt constructs and persists test-only approval/request/run relationships. It writes an approved decision and a CANCELLED execution request; the run defaults to SUCCEEDED and may be omitted to test request-only presence. Timestamps and settled_at follow the chosen status. These records deliberately support historical association cases and do not claim that the coordinator executed a provider effect, that approval was obtained from a real user, or that graph advancement occurred. Explicit commits belong to fixture setup, not to the production read projection.

history_truth snapshots eight named workspace/session/action/plan/source/request/run/event tables. Equality proves those selected rows did not change, not that every database table or external resource was untouched. The inherited catalogue setup trusts CPK_OPERATIONS_TEST_DATABASE_URL, creates a unique disposable schema and registers cleanup; it cannot establish the URL's isolation itself. The owning Operations test.sh provides Docker database isolation and is the only authorized executable route. No test execution was performed while writing this note.
