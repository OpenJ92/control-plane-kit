This module defines the revision-history store protocol and pure attribution helpers. It owns no connection, authorization, provider observation or mutation. HISTORY_SCOPE names the relation exposed by the concrete store: source-or-target sessions and exact-target attempts. Association is deliberately weaker than qualified provenance or accepted advancement evidence.

saved_revision_source requires all four retained inputs: source association, session, revision and start action. It reuses saved-preparation admission validators to correlate the immutable metadata, revision and original start commitment; it then requires the requested workspace/draft/revision. When a plan is supplied, its base graph/projection, desired graph/projection and desired generation must match the saved commitment. Missing or expected malformed evidence returns the fixed unavailable shape with null coordinates, not a best-effort guess. A successful projection returns only state=saved and the draft/revision/graph coordinates, not raw session metadata. Target-graph equality by itself never proves saved origin.

historical_advancement distinguishes no event and no action (none-recorded) from missing, duplicate or invalid paired evidence (unavailable). Exactly one pair must agree on session, execution request and timestamp, and satisfy CurrentGraphAdvancementResult's existing event/action transition contract. That includes graph/projection coordinates, digest, run/plan, event linkage and the recorded positive claim generation. The helper additionally checks public event/action identifier bounds and canonical timestamp form. Accepted output contains only event ID, action ID, instant and destination projection digest.

This is interpretation of historical evidence, not command replay: it does not consult today's claim, current pointer or provider state, and creates no receipt or event. A recorded accepted transition can remain historical truth after later pointer/claim changes. No pair does not prove that no external action ever happened. Selected ordinary validation failures become unavailable; this is not an arbitrary-object sandbox or a blanket catch of all exceptions. The caller/store remains responsible for supplying typed or safely decoded inputs and bounded collections.
