This internal pure join accepts supplied compatibility, the existing plan and
attempt identity, explicit original actor/session/request/effect context, and two
named sets of registered signing key, AuthorizedSecretUse and registered provider.
It checks the exact wait activity's workload and the original installed HttpCheck,
matching plan/projection/session, sample purpose/issuer/key ID/fingerprint/private
reference, deterministic key/provider/use identities, and original role binding.
It projects existing Core SecretResolutionGrants only after both roles validate.
The immutable handoff retains exact registration/public identity and original
check policy, receiver, gateway and route. No partial handoff is returned.

Stable `http-sample-use` correlation commits the original workspace, attempt,
actor/session/request, effect/fingerprint, check digest, plan/projection and role
target. It excludes private-reference/key selection and volatile sample ordinals.
The bounded versioned probe commits the role target digest and exact original key
registration. Replacing a key therefore keeps the lookup correlation but changes
the probe, refusing substitution of a retained binding. Neither creates a row.

All inputs are **supplied facts**, not provenance. The calculation loads nothing,
does not check current lifecycle or permission, and cannot establish that a plan
or check was admitted, rows were committed, or referenced resources remain eligible.
Reference registration IDs are preserved from the supplied use, not independently
loaded or verified as current reference admission. VERIFY_ONLY or retired facts
can be congruent; that never authorizes their use. Errors are fixed/redacted and
the handoff has no value-bearing repr. No secret material is read or returned.

The next actual producer must load and recheck original command/run/lease/prefix,
current workspace and role permission, exact original key/reference/provider
eligibility, atomically issue both role rows and commit. It must stop on a partial
pair or uncertain invocation. Both execution denials remain closed. Composition
must lower these Operations records into Core/public interpreter inputs; the
interpreter owns actual resolution, both fingerprint checks before pair emission,
fresh ordinal credentials and sampling inside the original check budget.
