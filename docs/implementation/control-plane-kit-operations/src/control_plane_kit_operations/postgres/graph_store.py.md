This file supplies three connection-bound stores: workspace state/pointers, authored graph versions and immutable realized projections. Stores never commit, authorize, plan or call providers. Current/desired labels are durable CPK claims; projection material is executable intent, not a fresh observation of running resources. Higher command owners must enforce approvals, run/effect evidence, lock order and public redaction before calling mutation methods.

Workspace create persists the supplied record; get optionally locks FOR UPDATE, while set_lifecycle reads once, replaces the lifecycle in memory, executes UPDATE and returns that constructed record without rereading or its own lock/transition policy. set_current_graph and set_desired_graph validate graph/projection ownership and update pointers; desired updates increment generation even when the graph is unchanged. These ordinary setters are not compare-and-set. If the projection argument is absent, _projection_for_source may construct and save an identity projection before the pointer UPDATE. If present, it checks relational workspace/source agreement without decoding the descriptor in that branch. All such preceding writes belong to the caller's rollback boundary.

compare_and_set_current_graph validates expected/replacement/desired projection ownership and requires replacement to equal the exact expected desired lineage. Its UPDATE predicates include current graph/projection, desired graph/projection and desired generation. Missing or mismatched expected-current projection returns None; replacement/desired validation can raise instead. A stale UPDATE also returns None. compare_and_set_desired_projection checks replacement source, leaves authored graph unchanged and conditionally increments generation for the exact expected desired tuple. These SQL fences neither inspect a successful run nor grant graph advancement authority.

Graph save encodes canonical UTC time before an INSERT, preserving the supplied descriptor/metadata. get is by graph ID, latest is workspace-scoped by descending version, and next_version is workspace MAX+1. The store does not lock version allocation; [authoring](../graph_authoring.py.md) holds the workspace lock around allocation/save. Schema uniqueness on workspace/version catches collision but is not a retry policy. GraphVersionRecord requires a Mapping descriptor; save is not a standalone semantic graph validator. This insert-only API does not make rows immune to direct database writes.

Projection save first validates time and authored-source workspace, then INSERTs with ON CONFLICT DO NOTHING. On conflict it resolves semantic identity (workspace, authored graph, kind, key) and requires the retained digest to equal the candidate. It can therefore return the old projection ID/attribution even if a caller supplied a new ID for equal material; different material under that identity conflicts. An unrelated primary-ID collision without a matching semantic row also conflicts. This is not unconditional upsert or material replacement. identity_for_authored returns a retained identity row or derives a deterministic value from the authored record; by itself it does not save the derived value. Pointer setters or publication callers own that save.

Projection record reconstruction decodes/re-encodes canonical graph material and verifies its digest, while ordinary graph reconstruction validates the shallower record fields and canonicalizes time. The current schema additionally enforces source/workspace FKs, projection semantic uniqueness, paired workspace lineage, nonnegative desired generation and graph/projection pointer agreement. Those constraints and constructors have different responsibilities; none validates every approved workflow or provider fact. Missing lookups include requested IDs in KeyError, and selected descriptor errors retain chained causes. Raw metadata, descriptors and exceptions are not certified safe public output.
