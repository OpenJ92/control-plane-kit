PostgresRevisionHistoryStore reads one exact workspace/draft/revision using the caller's connection. It commits nothing, changes no history and calls no provider. Parent existence is admitted separately; actor authorization belongs above the store. The request is revalidated at the owner boundary and restricted to preparation or attempt history. Presence and each page use the same relation definitions, not a scan of the current draft head or an inference from the current page's emptiness.

Preparations are the UNION of saved-source-associated sessions and sessions with plans targeting the revision's graph in the same workspace. UNION deduplicates sessions before chronology/identity seek and limit. Attempts require their own exact target plan, workspace/session-congruent execution request and matching run request/plan pair; another target plan in the same session is insufficient. Presence reports relation existence with completeness=association-records-only, without claiming all rows would pass detailed evidence validation.

Page SQL seeks strictly after (created_at, session_id/run_id), orders the same way and selects limit+1 candidates before evidence joins. The closed history page maximum is ten. Every candidate, including the hidden lookahead, is projected and validated; malformed required coordinates fail the whole page with a fixed error rather than silently dropping a row. ReadPage uses the last exposed candidate's cursor and enforces its encoded descriptor cap. Each main page query observes one statement's database view; parent admission is separate and later page calls can see later commits. There is no cross-call frozen snapshot, lock or global consistency guarantee here.

Bounded SQL projections replace text outside 1..2048 bytes or non-object/over-65536-byte JSON evidence with null. Query structure and field expressions are source constants; request values are bound parameters. Candidate output is bounded, not necessarily the planner's internal scan work. Advancement event/action probes fetch at most two candidates per side, enough to reject duplicates rather than pick an arbitrary receipt. These are historical evidence lookups, not a live lease check.

Typed decoders reconstruct optional source/start/receipt records, with UTC timestamp conversion bridging stored records and six-digit cursor instants. Expected decode failures yield unavailable attribution; malformed required page identity/plan/retry facts instead fail the page. Attempts validate retry predecessor identity, request/plan, previous attempt number and chronology, plus target graph and selected workspace/projection relationships. Status is the retained run status. The pure history helpers qualify saved origin and advancement; public output omits raw session metadata/action payloads and exposes only the selected relation fields and bounded receipts. This is structural projection, not arbitrary secret detection or evidence of current provider health.
