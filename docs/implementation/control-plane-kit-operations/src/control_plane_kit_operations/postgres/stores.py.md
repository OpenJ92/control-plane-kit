PostgresStoreBundle is a frozen dataclass composing the Operations PostgreSQL adapters around one supplied connection. It is not a domain service, transaction manager, schema installer, provider registry or authorization boundary. [PostgresUnitOfWork](unit_of_work.py.md) constructs the bundle on entry and owns physical commit/rollback/close; callers may also construct a bundle directly and then own those responsibilities themselves.

All adapter fields are init=False. __post_init__ assigns each with object.__setattr__, passing self.connection to every constructor. Composition is eager, not lazy: constructing the bundle creates all listed adapter objects. There is no conditional backend selection, connection pool, retry, workspace scope or capability admission in this file. The frozen container prevents ordinary field rebinding, not mutation of its stores or the connection they retain.

Membership groups workspace/authored/realized graph and draft/revision/preparation-source storage; product/runtime/ingress and secret authority/custody stores; session history, execution, effect intents/attempts/outcomes and compensation records; observations, gateway probes, node-control attempts/signing authority and delegation/rotation storage. Those imported adapters own their respective SQL and durable facts. The private _NodeControlSigningAuthorityStore is exposed here as a composed collaborator, not a new public command or permission grant. Package postgres exports make the bundle available to callers without transferring domain ownership to it.

Every constructor call visibly receives the same connection; the bundle itself exposes no commit, rollback or close façade and executes no SQL directly. That is a composition rule, not proof that all possible adapter implementations are effect-free or cannot commit. In particular, connection remains a public field and individual adapters retain it, so a caller can bypass UoW conventions using a saved connection/store reference. The PostgresConnection annotation is a protocol, not runtime enforcement of transactional mode, capability restrictions or lifecycle validity.

There is no local cleanup or partial-construction recovery. If a constructor raises, already-created collaborators are not individually closed; when this happens during UoW entry, its ordinary __exit__ cleanup is not entered. No claim is made that such a failure was observed. Connection acquisition, schema validity, isolation, locking, credentials, statement limits and provider authority remain at their existing owners. This file does not collect, redact or publish stored data, and merely obtaining a store does not authorize its operations.

The [UoW tests](../../../tests/test_unit_of_work.py.md) verify supplied connection identity, absence of bundle-level commit/rollback and selected lifecycle behavior. Their fake connection refuses SQL during construction. They do not enumerate each field's connection identity or establish all imported store semantics. The bundle docstring's future-store wording is historical scaffolding; the current source already constructs the listed domain stores.
