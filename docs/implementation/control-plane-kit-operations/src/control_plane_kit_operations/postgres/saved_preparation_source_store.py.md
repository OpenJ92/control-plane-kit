This store owns the four-column saved-preparation association: session, workspace, draft and revision. get validates exact string scope before SQL, selects by workspace/session and returns a typed SavedPreparationSourceRecord or None. insert accepts that exact record type and issues one INSERT in the caller's transaction. It does not create a session, admit preparation, authorize a caller, implement idempotency or commit. The schema's session primary key allows many sessions to share a revision while composite foreign keys enforce session/workspace and revision membership.

The separate current-row validator walks candidate sessions in session-ID order, 64 rows per batch, including the empty ID on its initial scan. Candidates have an association, a deployment_prepare_source marker or a saved-key prefix. LEFT JOINs retain malformed/missing source or revision evidence for rejection instead of hiding it with an inner join. SQL suppresses oversized selected text and non-object/oversized metadata before Python decoding: text fields use 1..2048 bytes and metadata at most 65536 bytes. These transport/batch bounds are not a total scan-time, database-work or transactional snapshot guarantee.

Rows are decoded through existing session, source and revision constructors and canonical timestamp conversion. validate_saved_preparation_source checks the closed saved metadata, recomputed session-command commitment and association/revision/graph agreement. It does not infer approval, execution, provider truth or a current graph selection. Required missing/malformed fields fail validation; this module neither repairs them nor reconstructs an erased association. If both the relation and all identifying saved metadata are erased, the candidate scan has no independent historical evidence to detect that origin.

Current-data validation invokes this scan and converts its expected type/value/record failures into CurrentRowDrift; schema installation owns the outer refusal policy. Ordinary get/insert do not perform the full retained-session scan or universally normalize database exceptions. The store trusts its caller's connection and authorization, and exposes internal record identifiers rather than a public redacted envelope.
