These four codecs bridge Operations text values and aware datetimes used by psycopg; they issue no SQL and own no transaction, schema migration, clock policy or provider effect. Record encoding first reuses the exact canonical UTC validator, then returns an aware UTC datetime. Record decoding requires a datetime with an available UTC offset, normalizes it to UTC and emits whole seconds when microseconds are zero, otherwise six fractional digits. A non-UTC database session therefore need not change the public instant's spelling.

Cursor encoding/decoding intentionally use another language: the exact UTC instant always contains six fractional digits, including .000000Z. Encoding requires exact str and a parse/decode round-trip equal to the original spelling; it does not accept equivalent offset or shortened aliases. Decoding adds the zero fraction when record rendering omitted it. These codecs preserve instants, not chronological ordering by textual spelling; stores must order/seek native temporal columns with their documented identity tie-breaks.

Expected encoding failures become fixed ValueError messages outside the raw parsing handler. Decode catches ordinary timezone/rendering failures and raises a fixed timezone-awareness error. The cursor encoder's failure branch samples datetime.now as a local placeholder, but the failed flag forces an error before any return; rejected input is never replaced by an accepted current timestamp. There is no retry, persistence repair or invented evidence time. BaseException is not swallowed, and these helpers do not establish a universal hostile-object boundary beyond the implemented checks.
