This store owns SQL for draft headers and immutable revision associations, scoped by workspace/draft. It uses the caller's connection, never commits, and does not authenticate, validate graph/product semantics, allocate graph versions or perform external effects. The [command service](../desired_topology_drafts.py.md) owns lock order, authority, replay and the atomic graph/revision/action transaction.

create admits a live revision-one header. append either inserts revision one or conditionally moves an undeleted header from the expected head to exactly its successor before inserting that revision. If the revision insert fails, callers must roll back the transaction containing the preceding UPDATE. The current schema's deferred head-to-revision FK permits header creation before the first revision in that transaction; revision-to-header and workspace/graph FKs, positive revisions and unique workspace/graph association provide additional relational constraints. These constraints do not independently provide all record string/time/graph-validation semantics.

get optionally uses FOR UPDATE; revision retrieves one scoped ordinal. Both raise fixed KeyError when absent and decode retained times through the canonical temporal codec and record constructors. create/append do not acquire the command's session/workspace/draft locks themselves. tombstone conditionally records actor/time on the exact expected live head, returning the retained header or conflict; it neither deletes rows nor checks references on its own.

has_references tests all revisions with SQL EXISTS: current graph, desired graph, plan base graph or plan desired graph. Plan status never releases retention. It materializes no revision/history list in Python. Its concurrency argument requires the caller's workspace-then-draft locks and the planning owner's shared workspace-lock discipline; invoking the method alone is not a race-free deletion authorization. It is not a search for arbitrary foreign-key references or provider ownership.

page supports only draft summaries and revision histories. Drafts, including tombstones, seek ascending creation instant/draft ID; revisions seek ordinal/graph ID within one workspace/draft. Queries fetch limit+1 candidates and delegate lookahead/cursor construction to ReadPage. Actual temporal cursor encoding preserves database cursor precision separately from record timestamp formatting. Typed ReadPageRequest supplies collection/scope/cursor compatibility. This is a bounded result page, not a frozen multipage snapshot or database query-cost guarantee. revisions_for_graph returns at most two associations as an ambiguity sentinel; the current unique workspace/graph constraint normally permits only one.

Full 135-line store, full command owner and catalogue tests read; selected actual current-schema catalogue constraints/index and previously reviewed temporal/read-page/UoW contracts checked. Tests exercise actual PostgreSQL through the owning package fixture, but none were run for this documentation. No migration, reset, schema repair, provider or cleanup behavior is introduced or authorized.
