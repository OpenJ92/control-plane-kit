This command service admits durable work, not external execution. `RequestPlanExecution` identifies a workspace/session/plan/approval, actor, normalized scopes, idempotency key and optional readiness references. A successful fresh call writes a queued execution request and correlated `ADMIT_EXECUTION` action in one unit of work. It does not approve a plan, start a run, call an interpreter, advance a graph, probe a database or rotate a key. The caller supplies actor/scopes; this module is not an HTTP credential verifier.

## Fresh admission and replay

`execute` requires `PLAN_EXECUTE` before replay. It takes transaction-scoped action and admission idempotency locks, looks up the workspace/key receipt, and only then enters fresh-admission checks. The fingerprint covers command kind, workspace, session, plan, approval-request ID, actor and sorted readiness; it deliberately does not include actor scopes. Matching replay retrieves the existing request and correlated action without allocating new IDs or rechecking current approval, session, graph or delivery truth. The request is the stored request as read now, not a frozen original queued-status snapshot. Changed intent conflicts; missing/inconsistent action evidence fails. This is admission receipt replay, not permission to redispatch an effect or the coordinator's separate execute-command replay contract.

For new work, the service locks session/workspace rows and requires the matching open session, a planned nonempty plan with no review blockers, and an approved closed subject. Ordinary plan approvals must identify the plan/session and match the scope, destructive flag and maximum risk derived by Core [ApprovalPolicy](../../../../../control-plane-kit-core/src/control_plane_kit_core/policies.py) from the persisted plan. The service consumes the durable decision; it does not recreate the approval workflow's principal-separation decision.

Authored current/desired IDs, realized projection IDs and desired revision must still match the plan. Missing explicit projection IDs use the store's authored identity projection. Each loaded projection must belong to the workspace and authored graph. This owner trusts the ordinary persisted canonical plan; unlike its rotation-child branch, it does not recompile every ordinary plan here. [records.py](../../../../../control-plane-kit-operations/src/control_plane_kit_operations/records.py), planning and graph stores own the preceding durable contracts.

Any authority reference in either graph requires `RUNTIME_AUTHORITY_USE`; any public ingress in either requires `INGRESS_AUTHORITY_USE`. Registration permission is not use permission. For planned StartNode/ReconcileNode declarations, the selected [runtime-authority delivery check](../../../../../control-plane-kit-operations/src/control_plane_kit_operations/runtime_authorities.py) requires exact material, one active admission, workspace and enclosing runtime-authority agreement. It is an admission snapshot, not credential resolution, provider inspection or a perpetual execution grant. Teardown is not subjected to this start/reconcile delivery check. Replayed receipts likewise survive later delivery revocation; execution-time checks remain their owners' responsibility.

## Readiness and rotation boundaries

External readiness is required only for the identified Postgres socket switches and reconciliations whose consumer has a changed environment-bound Postgres edge. Supplied activity IDs must equal that required set. `ExternalReadinessAttestation` restricts references to a namespaced identifier of at most 256 characters; it rejects URLs and arbitrary text by shape. The reference is retained in action evidence but never dereferenced here. Its presence does not establish migration completion, database health, data safety or the truth of the caller's assertion; identifier syntax is not a universal secret detector.

A gateway-rotation approval is not a blanket plan approval. The locked durable rotation must reproduce its Core [approval subject](../../../../../control-plane-kit-core/src/control_plane_kit_core/approval_subjects.py) and digest, decision identities/scope, and approval-request action correlation. Only KEY_GENERATED (overlap) or DRAINING_OLD_GRANTS (retirement) selects a child phase. Exact workspace/projection/revision lineage, phase-named projection identity/kind/key, one matching publication action and its rotation version must agree. The service re-derives the desired verifier graph and recompiles the realized diff, requiring exact plan equality.

The imported [rotation projection owner](../../../../../control-plane-kit-operations/src/control_plane_kit_operations/gateway_key_rotation_projection.py) checks the exact old/new key set, custody-reference agreement, authored binding and current verifier material: active-A/verify-B with current A for overlap, verify-A/active-B with current A+B for retirement. Admission neither generates secret material nor proves a running gateway adopted those verifiers. Retirement's trusted drain-time check belongs to publication, not a new clock check in this service. Future edits must preserve that division rather than imply autonomous rotation or cleanup.

## Transactions, evidence and maintenance

[PostgresUnitOfWork](../../../../../control-plane-kit-operations/src/control_plane_kit_operations/postgres/unit_of_work.py) owns commit/rollback/close; `commit()` requests commit on successful context exit. [Execution](../../../../../control-plane-kit-operations/src/control_plane_kit_operations/postgres/execution.py) and [history](../../../../../control-plane-kit-operations/src/control_plane_kit_operations/postgres/activity_history.py) stores share that connection and use advisory transaction locks for the scoped keys. Request/action insertion is atomic, including rollback on late action failure. No database transaction crosses a provider call in this owner.

Descriptors/actions retain IDs, lineage and readiness references rather than provider bodies or credentials. Errors may include supplied activity/projection IDs and chained store/codec errors; this is not a global error-text cap or sanitizer. Preserve bounded/redacted public projection at its actual owner instead of advertising every internal exception as safe output.
