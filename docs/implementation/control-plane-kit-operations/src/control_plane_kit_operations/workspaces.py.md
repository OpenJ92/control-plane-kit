WorkspaceCommandService creates local workspace truth with an empty authored current graph and its identity realized projection. It does not deploy a runtime, inspect providers, select a desired topology or create an operation session/action. The service commits one UoW; [workspace/graph stores](./postgres/graph_store.py.md) share that transaction. No credential or scope check exists here: the public planning adapter derives trusted actor/workspace and requires hub.instance.create before service entry.

CreateWorkspace checks nonblank workspace/name/actor text, an IdempotencyKey and Mapping metadata. These local checks have no aggregate size or deep-redaction policy. New creation allocates one graph ID and time, constructs a version-one graph record named empty with bootstrap/key metadata, inserts the workspace, saves the graph and sets current lineage. The store may derive/save the identity projection. Desired remains unassigned and lifecycle retains its record default. All writes commit together; no partial-store commit is authorized.

Existing workspace handling is replay by workspace ID plus matching name, not by a durable command-key receipt. It requires a current graph pointer, loads that graph and returns the existing workspace/current graph with replayed=true before clock/ID allocation. It does not compare the supplied key, actor or metadata with the original request, nor require the current graph still be the initial empty graph. Later pointer changes can therefore affect this returned replay result; it is not an immutable copy of the first response. Different name or missing current pointer raises; missing graph and unexpected database failures can propagate. No lock/upsert/retry serializes concurrent first creation in this owner; database uniqueness is not translated into successful replay.

The result descriptor omits workspace metadata and graph bodies but returns supplied/stored names, lifecycle and lineage coordinates. It is not an arbitrary string sanitizer. The full graph record still contains bootstrap idempotency metadata, and the workspace retains the supplied Mapping. Do not infer safe logging of internal records/exceptions or provider convergence from a successful creation receipt.
