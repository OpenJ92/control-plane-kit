This is a thin read-service boundary over RevisionHistoryStore, not another history relation or execution state machine. page checks the requested workspace and returns the store's page unchanged. presence delegates without calling the workspace callback: the draft-detail caller has already admitted its workspace, while the concrete store admits the revision parent. Neither method establishes actor authorization on its own.

Both paths require the configured history store and translate KeyError into fixed ReadModelError("missing draft revision") with suppressed cause. Missing configuration instead reports "revision history is unavailable". Other failures propagate; this wrapper does not provide a universal malformed-value or exception-redaction boundary.

The actual Postgres owner scopes preparations to the union of saved-source sessions and exact target-graph sessions, and attempts to workspace/session/plan-congruent requests and runs targeting that revision. Presence explicitly reports "association-records-only" completeness. Page projection validates retained source and advancement evidence through the existing Operations helpers; target membership alone does not prove saved-source provenance. This wrapper neither recomputes those relations nor turns a recorded successful status into current provider truth.

Pagination, bounds and cursor admission belong to ReadPageRequest and the store. The concrete store uses chronological identity seek with a bounded lookahead and validates/project-caps the resulting page. Separate calls can observe later commits; the projection promises neither a cross-page frozen snapshot nor transactional consistency between a detail and its history. Stores use the caller's connection; this module opens no transaction, commits nothing, calls no provider and authorizes no retry, cleanup or graph advancement.
