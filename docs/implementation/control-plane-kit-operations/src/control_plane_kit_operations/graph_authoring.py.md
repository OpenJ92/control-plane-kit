This lower-level owner publishes a new authored graph version and its identity realized projection as desired workspace truth. It does not create a saved draft, plan, approval, run or provider effect. GraphAuthoringService owns one UoW/commit; set_desired_graph_in_unit_of_work lets the session/action command in planning.py include those writes in its own transaction. The standalone service has no idempotency key, action record, session-open check or authorization policy; public callers must enter through the appropriate authenticated command owner.

SetDesiredGraphCommand carries workspace/actor, graph and expected desired graph/projection/generation. Its text validator is nonempty, at most 512 characters and excludes character codes below 32; it does not reject whitespace-only text or every Unicode control category. Generation is an exact nonnegative int without a local bigint maximum or paired-pointer rule. The result groups workspace, graph version, projection and product references; SelectableProduct is a simple reference/display-name/description value, not a general content scrubber despite its secret-free intent.

The helper extracts product references before locking the workspace, compares the complete expected desired tuple, requires each referenced descriptor to be active in that workspace, saves a new graph version, obtains/saves its identity projection and updates desired graph/projection while incrementing generation. Graph-store version allocation is MAX+1 under the caller's workspace lock. All these writes share the caller transaction; no current graph pointer or external resource changes. The outer service allocates its graph ID and clock before helper admission, including on a stale request.

Product extraction examines product_identity and product_descriptor_digest node metadata. Nodes without either are skipped; partial/nonstring pairs reject. Identities parse namespace/name/integer revision and pair with a Core digest, then deduplicate/sort. Lookup uses the exact descriptor digest, not just product name or OCI image identity. This proves admitted references, not that arbitrary node configuration still matches its originating product. There is no explicit validate_graph(...).require_valid call in this file: codecs/record constructors and selected stores supply their own representation checks, not an asserted complete deployment-validity proof. Do not transplant the stricter saved-draft admission claim onto this owner.

selectable_products reads active workspace registrations and projects reference/name/description without committing writes or paging the result. Neither authoring nor selection resolves credentials, pulls images or checks provider health. Input graph metadata and display strings are retained input, not redacted by this owner. Errors can include a submitted node ID or product identity and chain underlying exceptions; public bounded-error policy must be supplied by the relevant adapter, not inferred here.
